How the interview works, and how to mock it yourself

In one sentenceYou get 25 minutes, a Snack and a handout; the TA watches how you plan, code, debug and talk, so a clear process matters more than a finished app.

The format

25 minutesOne problem, worked live in front of a TA. Arrive five minutes early with a charged laptop.
Expo SnackThe TA opens a Snack on your computer. You code in the browser and preview on the Web, iOS or Android tab.
HandoutA reference screenshot of the finished app plus a step-by-step breakdown of the parts.
Ask questionsClarifying questions are welcome. The TA can't hand you the answer but may point things out to get you unstuck.
You may be moved onThe TA may ask you to skip to a later part. That is normal and lets them see more of your skills.
Process, not completionYou are not expected to finish. The TA observes how you plan, code, debug and explain.

What you may use

Allowed
  • The open internet, including Google Search's AI overview.
  • Optionally, one page of handwritten notes in English, front and back, pen and paper. You hand it to the TA at the end.
Not allowed
  • Any other AI tool.
  • Homework solutions, or solution-like code, even if handwritten.

You do not need notes to do well. If you bring a page, fill it with syntax shapes using generic names (items, setItems, Item, onAdd, ChildProps) and error → fix pairs, not app-specific code. Something like addMenuItem or ItemCard written out in full looks like solution code, which the rules forbid even handwritten.

The 25-minute game plan

Each phase builds on the last, and the app runs at the end of every phase. If the TA moves you on, you still have working code to talk about. The times are a guide, not a rule.

What a 2-minute sketch looks like

Before typing, draw the boxes and arrows. Ask two questions: where does each piece of state live? and which way does each piece of data travel?

What the interviewer is looking for

These six behaviors are what each mock's self-check rubric is built from. Read them now, and skim them once more just before you walk in.

Writes effective RN code with TypeScript

Readable components, sensible names, types on props and callbacks, inference everywhere else.

Example: type AddItemFormProps = { onAdd: (item: MenuItem) => void }

Uses state correctly, with immutable updates

State for anything that changes; the declared setter; new arrays and objects, never push or direct edits.

Example: setMenu([...menu, item])

Renders lists with map and keys

Data array to component array, the right brackets after =>, a stable key on the outer element.

Example: menu.map((item) => (<ItemCard key={item.name} item={item} />))

Passes data down and callbacks up

State lives in the parent; the child receives values and a function, and calls it inside an arrow.

Example: onPress={() => onAdd({ name, popular })}

Uses core components and props correctly

View, Text, ScrollView, TextInput, Switch, Pressable, StyleSheet, each with the right props.

Example: <Switch value={popular} onValueChange={setPopular} />

Debugs independently and thinks aloud

Runs early and often, reads the error message, searches for concepts, and narrates the plan.

Example: “The squiggle says item isn't a prop yet, so I need a props type.”

How to run a mock on yourself

  1. Pick one mock and do not scroll past its handout. The parts, hints and solutions sit below it.
  2. Open a blank Snack at snack.expo.dev, rename the file to App.tsx, and paste the starter code. Check that it runs.
  3. Press Start on the mock's timer. It stays pinned at the top while you scroll through that mock, and it turns red at 5:00 left.
  4. Spend the first two minutes reading and sketching on paper. Then work through the parts in order, and say your plan out loud. Talking to an empty room feels odd, but it is the skill being observed.
  5. Stuck for about two minutes? Open Hint 1, then Hint 2, then Hint 3. If one part blocks you for five minutes, move to the next part, just as a TA might ask you to.
  6. At 25:00, stop typing. Tick the rubric honestly, then read the model solutions and the “Why this works” notes. Finish with the review routine in After a mock.

A 60-second talk-aloud script

Say something close to this in your first minute, before you type. It shows the TA your plan, and it settles your nerves.

  1. Read: “Let me read every part first, so I know where this is going.”
  2. Data: “The data is an array of MenuItems, so I'll keep it in state in App with useState(menuItems).”
  3. List: “I'll map each item to an ItemCard inside a ScrollView, with a key on each card.”
  4. Form: “The form owns its own text and switch state. The list lives in App, so App passes an onAdd callback down and the form calls it.”
  5. Order: “I'll get it on screen in plain JavaScript first and run it after each step, then add the types. Starting with Part 1.”
If the interviewer says “move on”: stub the part with hard-coded values and keep going. For example, render one <ItemCard item={{ name: "Test", popular: true }} /> instead of the map, or have the button call onAdd({ name: "Test", popular: false }). Say “I'll stub this and come back to it,” and come back if time remains. The later parts still get something real to work with.

Snack quirks worth knowing

  • Red squiggles usually do not stop the app. They are TypeScript type errors; Snack still runs your code. That is why “JS first, types second” works: get it running, then fix the squiggles.
  • A red error screen is a runtime error. Read the message and the line number on it first (for example App.tsx:42), then look at that line.
  • The Web preview can behave differently from a phone. A string outside <Text>, or a stray 0 from count && …, may only crash on iOS or Android. Check the iOS or Android tab before you call a part done.
  • onChangeText={setName} is fine, because it passes the new string. onPress={setX} is not the same: Pressable passes an event object, so your state would become that event. Write onPress={() => setX(…)}.
  • Passing vs calling: onPress={onAdd(item)} calls onAdd during render, which can cause “Too many re-renders.” Pass a function instead: onPress={() => onAdd(item)}.
Common trap. Coding silently for ten minutes, then running the app for the first time. Run after every small step. A red screen you get one minute after a change points straight at that change.

Rapid-fire on: statemap & keysScrollView
Your task. In App, put menuItems into state. Turn each item into an <ItemCard /> with map, and render the cards inside a ScrollView under the title. Pass each card its item as a prop called item. The same map with a block body. Both are correct; the braces version needs return.

const cards = menu.map((item) => {
  return <ItemCard key={item.name} item={item} />;
});
Why this works. map calls your arrow function once per item and collects the return values into a new array. With no { right after =>, the expression is returned automatically, so the one-liner returns the JSX. The ( ) around the JSX are just grouping, so it can span several lines. The key goes on the outermost element you return from map, so React can tell the cards apart when the list changes. The menu lives in state, not a plain variable, because Part 4 will add items, and only a setter call makes React re-render. flex: 1 on the ScrollView lets it take the leftover height, which keeps the form pinned below it later.
Common trap. Writing menu.map((item) => { <ItemCard item={item} /> }). The braces start a function body with no return, so every call returns undefined and nothing renders, with no error. Either swap the braces for parentheses or add return.

Part 4: Make Add item work with a callback

about 7 min
Rapid-fire on: callbacksarrow wrappersimmutable addfunction types
Your task. Define addMenuItem(item: MenuItem) in App. Pass it to AddItemForm as a prop called onAdd. When Add item is pressed, the form calls onAdd with a new MenuItem built from name and popular, then clears the text input.
Clarifying question you could ask“After adding, should the Popular? switch also reset to off?” (Either is fine. Asking shows you are thinking about the user.)
Hint 1 · Nudge

Which component owns menu? Only the component that owns a piece of state can change it, so the code that adds to the menu must live there. How can the form reach it?

Hint 2 · Pointer

A parent can hand a child a function as a prop. Type that prop as a function type, type AddItemFormProps = { onAdd: (item: MenuItem) => void };. The child calls it with an object of the MenuItem shape.

      </Pressable>

Why this works. Data flows down as props, and requests flow up through callbacks. App passes addMenuItem down under the name onAdd. When the form calls onAdd(...), it is really running addMenuItem inside App, where setMenu exists. { name, popular } is shorthand for { name: name, popular: popular }, an object that matches MenuItem. [...menu, item] builds a new array with the old items plus the new one, so React sees a change and re-renders. The direct form setMenu([...menu, item]) is the simple default. The updater form setMenu((prev) => [...prev, item]) is also valid, and it is the safer choice when the new value depends on the old one across several updates or inside a timer. The arrow () => ... hands onPress a function to call later, on tap.
Common trap. setMenu(menu => {...menu, item}) has two separate bugs. First, { right after => starts a function body, not an object, so nothing is returned. Second, menu is an array, so the copy needs square brackets: [...menu, item]. Fixed: setMenu((prev) => [...prev, item]). Also call the setter you declared (setMenu), not a generic setState, and keep the arrow: onPress={onAdd({ name, popular })} calls onAdd during render instead of on tap.

  popular: boolean;
};

  const canAdd = name.trim().length > 0; // Stretch: disable when empty

    onAdd({ name: name.trim(), popular }); // build the object the type expects
    setName("");                           // clear the input
    setPopular(false);
  };

  return (
    <View style={styles.form}>
      <TextInput
        style={styles.input}
        value={name}
        onChangeText={setName}
        placeholder="New item name"
      />
      <View style={styles.switchRow}>
        <Text style={styles.switchLabel}>Popular?</Text>
        <Switch value={popular} onValueChange={setPopular} />
      </View>
      <Pressable
        style={[styles.addButton, !canAdd && styles.addButtonDisabled]}
        onPress={handleAdd}
        disabled={!canAdd}
      >
        <Text style={styles.addButtonText}>Add item</Text>
      </Pressable>
    </View>
  );
};

Q1What is the difference between (x) => x * 2 and (x) => { x * 2 }?
Hint

One of them has an implicit return. Which?

Model answer

The first has an expression body, so it returns x * 2 automatically. The second has a block body, because the braces start a function body, and a block body only returns what you return. It returns undefined. Write (x) => { return x * 2; } if you want braces.

Q2How do you return an object literal from a one-line arrow function?
Hint

What does { mean right after =>?

Model answer

Wrap the object in parentheses: () => ({ name: "Latte", popular: true }). Without them, JavaScript reads { as the start of a function body, not an object. This is why menu => {...menu, item} does not do what it looks like.

const makeItem = (name: string) => ({ name, popular: false });
Q3What is the difference between onPress={handleAdd}, onPress={handleAdd()} and onPress={() => handleAdd(item)}?
Hint

Which ones hand over a function, and which one calls it immediately?

Model answer

onPress={handleAdd} passes the function itself, to be called on tap. onPress={() => handleAdd(item)} passes a new function that calls handleAdd with an argument on tap. onPress={handleAdd()} calls it during render and passes its return value. If it sets state, that causes “Too many re-renders.”

Q4What is an anonymous function, and where do you use them in React Native?
Hint

Think of three props that take functions.

Model answer

An anonymous function is a function without a name, usually an arrow written inline, such as () => setCount(count + 1). In React Native you write them constantly: in onPress, in onChangeText, as the callback passed to map, and inside useEffect and setInterval. Functions are values in JavaScript, so you can pass them around like numbers or strings.

Q5When must you use parentheses around arrow parameters?
Hint

Count the parameters, and think about TypeScript.

Model answer

With exactly one untyped parameter, parentheses are optional: x => x * 2. You need them for zero parameters () =>, two or more (a, b) =>, and whenever you add a type, as in (item: MenuItem) =>. Always writing them is a simple habit that avoids the question.

Q6Why does onChangeText={setName} work even though there is no arrow?
Hint

What does TextInput pass to onChangeText?

Model answer

TextInput calls onChangeText with one argument, the new string. setName is a function that takes the new value, so passing it directly is fine. It is equivalent to onChangeText={(text) => setName(text)}. Use the arrow version when you need to do anything extra, such as trimming.

Q7What does map return, and does it change the original array?
Hint

New array or same array?

Model answer

map returns a new array of the same length, where each element is whatever your callback returned. It does not change the original. In React you use it to turn an array of data into an array of JSX elements.

const names = menu.map((item) => item.name); // string[]
Q8Why does every element returned from map need a key, and what makes a good key?
Hint

How does React tell list items apart between renders?

Model answer

React uses keys to match each item in the new render with the same item in the previous render, so it updates the right one when items are added, removed or reordered. A good key is unique among siblings and stable. Use a unique id if the data has one (key={item.id}); key={item.name} is fine only if names are unique. Avoid Math.random(), and avoid the index when items can be inserted or removed.

On the outermost element returned from map, for example <ItemCard key={item.name} item={item} />. A key inside ItemCard does nothing for the list. key is also not passed to the child as a prop, so pass the id separately if the child needs it.

Q13Why is menu.push(item); setMenu(menu); wrong?
Hint

What does React compare to decide whether to re-render?

Model answer

push mutates the existing array, and then you pass React the same array back. React compares the old and new values, sees the same array, and may skip the re-render, so the screen does not update. Make a new array instead: setMenu([...menu, item]).

Q14Fix this: setMenu(menu => {...menu, item}).
Hint

There are two problems: one about { after =>, one about arrays versus objects.

Model answer

First, { right after => starts a function body, so nothing is returned. Second, menu is an array, so the copy uses square brackets. Both of these work: the direct form setMenu([...menu, item]), and the updater form setMenu((prev) => [...prev, item]). Also make sure you call the setter you declared.

Q15How do you add an item to the start of an array in state?
Hint

Where does the new item go relative to the spread?

Model answer

Put the new item before the spread: setMenu([item, ...menu]). Spread copies the old elements in order, so whatever you write before or after it decides the position.

Q16How do you toggle one field on one item in an array of objects?
Hint

You need a new array and a new object for the changed item.

Model answer

Use map to build a new array. For the matching item, return a copy with the field overridden. Return every other item unchanged. Later properties in an object literal win, so done after ...habit overrides the old value.

));

Which method keeps the items that pass a test?

Use filter and keep every item except the one to remove: setHabits(habits.filter((habit) => habit.id !== id)). filter returns a new array and leaves the old one alone. Avoid splice, which mutates.

A new object with every property of item copied over, and then popular set to true. Properties written later win. The original item is unchanged. Spread is shallow, so nested objects are shared, not copied.

Q21What are the two ways to call a state setter, and when do you use each?

The direct form passes the next value: setMenu([...menu, item]). It is the simple default and fine for most handlers. When can't TypeScript infer from the initial value?

Model answer

When the initial value does not show the full type, usually an empty array or null. useState([]) would give you an array of never. Write useState<MenuItem[]>([]) instead. When the initial value already has the right type, such as useState(menuItems), let inference do the work.

Q43What does ? mean in type Song = { title: string; note?: string }?
Hint

Optional.

Model answer

note is an optional property. An object can leave it out, and its type is string | undefined, so check it before using it.

Q44What is the difference between a type alias and an interface for props?
Hint

For this course, does it matter?

Model answer

Both describe the shape of an object, and for props they are interchangeable. type can also name unions, such as type Size = "S" | "M" | "L". Pick one style and stay consistent; the starter code here uses type.

Q45What is a good order of work when TypeScript errors slow you down?
Hint

Logic first, or types first?

Model answer

Get the logic working first, the way you would in plain JavaScript, and let inference type most things. Then add types where TypeScript needs them: props, callback props, and empty useState arrays. Read each red squiggle's message; it usually names the expected and actual types. Type errors do not stop a Snack from running.

Q46What is the default flexDirection in React Native, and how does that differ from the web?
Hint

Column or row?

Model answer

React Native defaults to column, so children stack top to bottom. The web defaults to row. To put a name and a badge side by side, set flexDirection: "row" on their parent.

Q47justifyContent versus alignItems: what does each control?
Hint

Main axis versus cross axis.

Model answer

justifyContent positions children along the main axis, the direction of flexDirection. alignItems positions them along the cross axis, perpendicular to it. In a row, justifyContent: "space-between" spreads items left to right, and alignItems: "center" centers them vertically.

Q48How do you apply a style only when a condition is true?
Hint

Style arrays.

Model answer

Pass an array of styles. Later entries override earlier ones, and false, null or undefined entries are ignored. So style={[styles.row, habit.done && styles.rowDone]} adds rowDone only for done habits. Pressable can also take a function that receives pressed, for a tap effect.

style={[styles.card, item.popular && styles.popularCard]}
style={({ pressed }) => [styles.btn, pressed && { opacity: 0.6 }]}  // on a Pressable
Q49What does flex: 1 do?
Hint

Available space along the main axis.

Model answer

It makes a component grow to fill the available space along its parent's main axis. On the root View it fills the screen. On a ScrollView above a form, it takes the leftover height so the form stays at the bottom.

Effects & Promises 4 questions

ConceptPracticeCheat sheet
Q50What do the three dependency-array options of useEffect mean?
Hint

None, empty, and with values.

Model answer

No array: run after every render. []: run once, after the first render. [a, b]: run after the first render and then whenever a or b changes.

Q51When does an effect's cleanup function run?
Hint

Two moments.

Model answer

Right before the effect re-runs because its dependencies changed, and when the component unmounts. That is where you call clearInterval or clearTimeout, so old timers do not pile up.

useEffect(() => {
  const id = setInterval(() => setSeconds((s) => s + 1), 1000);
  return () => clearInterval(id);
}, []);
Q52Why use setSeconds((s) => s + 1) instead of setSeconds(seconds + 1) inside setInterval?
Hint

Stale closure: which render's seconds does the interval see?

Model answer

The interval's callback was created during one render, so it keeps seeing that render's seconds. With the direct form it would set the same value on every tick. The updater form receives the latest value from React each time, so it counts correctly.

Q53How do you use a Promise-returning function such as loadTasks() in a component?
Hint

useEffect with [] plus .then.

Model answer

Call it inside useEffect with [] so it runs once, and use .then to put the result in state. Do not make the effect function itself async, because an effect must return nothing or a cleanup function.

useEffect(() => {
  loadTasks().then((loaded) => setTasks(loaded));
}, []);

Mental model 3 questions

ConceptPracticeCheat sheet
Q54What does “UI is a function of state” mean?
Hint

What runs when state changes?

Model answer

Your component is a function that takes props and state and returns what the screen should look like. You never edit the screen directly. You change state, React calls your function once more, and it updates the screen to match the new result.

Q55What happens, step by step, when the user taps a button that calls setCount(count + 1)?
Hint

Event, request, render, update.

Model answer

The onPress arrow runs and calls the setter, which queues the new value and asks React to re-render. React re-runs the component function, useState returns the new value, and the new JSX is compared with the old JSX. Only what changed is updated on screen.

Q56If a parent re-renders, what happens to its children?
Hint

Subtree.

Model answer

By default the children re-render too, because the parent's new JSX includes them with possibly new props. A state change re-renders the component that owns the state and the subtree below it, not the whole app.
